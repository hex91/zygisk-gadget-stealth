## 1. 安装与加载

```
ksud module install /data/local/tmp/gs.zip
  -> customize.sh 解压出 libgcore.so(24,872,296 B) / libgcore32.so(15,700,304 B)
  -> 写 settings.conf / hook.js / libgcore*.config
  -> module.prop description 刷新
adb reboot
  -> /data/adb/zygisksu/modules_info:
       zygisk_gadget_stealth 64 fd=11 ... sz=311296
       zygisk_gadget_stealth 32 fd=15 ... sz=167936
```

**踩坑 1（SELinux）**：第一次安装后注入失败，状态文件报 `ok=0;detail=dlopen-failed`。logcat 显示：

```
avc: denied { execute } for path="/data/local/tmp/.gsys/libgcore.so"
  scontext=u:r:untrusted_app:s0 tcontext=u:object_r:shell_data_file:s0
```

`/data/local/tmp` 下用 `cat >` 生成的文件是 `shell_data_file`，App 域不能执行；参考项目 ZygiskFrida 的 so 是 `u:object_r:system_file:s0`。修复：`customize.sh` 与每次 `reload` 执行 `chcon -R u:object_r:system_file:s0 "$DATA"`。修复后 `detail=xdl`，注入成功。

**踩坑 2（编译）**：Windows 上首次用 NDK 编译约 2 分钟且脚本末尾 `llvm-nm` 无输出，看起来像卡死；实际两个 ABI 的 so 已生成、`zygisk_module_entry` 导出正常。改成增量编译 + `grep -a` 扫字节校验后，二次构建几秒完成。

**踩坑 3（WebUI 协议）**：SukiSU 4.1.0 的 `ksu.exec(cmd)` 同步返回 stdout **最后一行**，第二参数是 options 不是回调。所有 WebUI 命令都设计成单行 `key=value`；多行输出或回调写法会卡 20 秒超时。

## 3. listen 模式（交互 + 双路共存）

```
sh gadget_ctl.sh mode listen
  -> libgcore.config = {"type":"listen","port":27052,
       "on_port_conflict":"pick-next","on_load":"resume"}
force-stop + 重启目标 App
```

| 项 | 实测 |
|---|---|
| 端口 | `127.0.0.1:27052` 监听者 = `9863/com.hex91.appinspector` |
| `frida-ps -H 127.0.0.1:27052` | `9863  Gadget` |
| 加载脚本返回 | `{'ver':'17.5.2','arch':'arm64','platform':'linux','pid':9863,'modules':338}` |
| `frida-ps -H 127.0.0.1:39527` | 整机进程正常列出（`sysmon` pid 6455） |

结论：gadget 与 frida-server 两路并存互不干扰；gadget 版本与 PC 客户端 17.5.2 严格一致。
