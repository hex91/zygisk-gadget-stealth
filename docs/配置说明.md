# 配置说明

## 配置文件位置

| 文件 | 路径 | 作用 |
|---|---|---|
| 主配置 | `/data/local/tmp/.gsys/settings.conf` | 模式、端口、延迟、目标、去特征开关 |
| 脚本 | `/data/local/tmp/.gsys/hook.js` | `script` 模式加载的 hook 脚本 |
| gadget 行为配置 | `/data/local/tmp/.gsys/libgcore.config` | 由 `reload` 自动生成，**不要手改** |
| 32 位行为配置 | `/data/local/tmp/.gsys/libgcore32.config` | 同上 |
| 数据目录重定向 | `/data/local/tmp/.gsys_redirect` | 内容为绝对路径，改数据目录用 |
| 状态文件 | `/data/data/<包名>/.gs_state.<pid>` | native 注入后写入，管理端只读 |

> `settings.conf` 是纯文本 `key=value`，`#` 开头是注释。之所以不用 JSON：Zygisk 模块会在**每个 App 启动时**被加载，纯文本解析没有依赖、不会因为配置写错让无关 App 崩溃。

## 全部参数

| 键 | 默认 | 取值 | 说明 |
|---|---|---|---|
| `enabled` | `1` | `0` / `1` | 全局总开关。`0` 时所有 App 都不注入 |
| `mode` | `script` | `script` / `listen` | `script`：无端口、App 启动自动执行 `hook.js`；`listen`：监听端口等客户端连接 |
| `port` | `27052` | 1–65535 | 仅 `listen` 有效。避开 27042（gadget 默认）和 frida-server 端口 |
| `delay_ms` | `1200` | 0–1000000 | 注入延迟。进程名变成目标包名后再等这么久，让启动期完整性检查先跑完 |
| `lib_name` | `libgcore.so` | 文件名 | 64 位 gadget 的伪装名。不要带 `frida` / `gadget` 字样 |
| `lib_name32` | `libgcore32.so` | 文件名 | 32 位 gadget 的伪装名 |
| `hide_maps` | `1` | `0` / `1` | 把 gadget 的 `/proc/self/maps` 段用 `mremap` 重映射成匿名内存 |
| `hide_module_map` | `0` | `0` / `1` | 把 Zygisk 模块自身 so 也匿名化（实验性）。实测 Zygisk Next 本来就用 memfd 加载，maps 里看不到模块路径，通常不需要开 |
| `hide_threads` | `1` | `0` / `1` | 守护线程持续把 `gum-js-loop` / `frida-gadget` / `gmain` / `gdbus` 改名 |
| `no_log` | `1` | `0` / `1` | 不向 logcat 输出。调试时设 `0`，用 `gadget_ctl.sh log` 看 |
| `write_state` | `1` | `0` / `1` | 写 `.gs_state.<pid>` 供状态面板读取。极敏感场景可关 |
| `thread_alias` | `auto` | `auto` / 自定义字符串 | `auto` 从真实 ART/App 线程名池轮换；自定义则用 `<前7字符>-<tid>` |
| `target` | `com.hex91.appinspector,1,1200` | `包名,启用,延迟ms` | 可写多行 |

### `target` 行格式

```
target=<包名>,<enabled 0|1>,<delay_ms>
```

第三个字段会覆盖全局 `delay_ms`。例：

```
target=com.example.app,1,0            # 立即注入
target=com.example.heavy,1,3000       # 等 3 秒再注入
target=com.example.off,0,1200         # 保留配置但不注入
```

## 改配置的三种方式

### ① WebUI（推荐）

模块卡片点「打开」→ 状态卡下方直接切模式、改端口/延迟、增删启停目标、切去特征开关。

### ② 设备命令

```bash
CTL=/data/adb/modules/zygisk_gadget_stealth/gadget_ctl.sh
su -c "sh $CTL mode listen"
su -c "sh $CTL port 27111"
su -c "sh $CTL delay 2000"
su -c "sh $CTL add com.example.app"
su -c "sh $CTL disable com.example.app"
su -c "sh $CTL stealth no_log 0"
su -c "sh $CTL reload"
```

所有写操作最后都会自动 `reload`（重新生成 gadget config + 刷新模块说明 + 清旧状态），并返回一行 `OK;msg=...`。

### ③ 直接编辑

```bash
adb shell su -c "sed -i 's/^mode=.*/mode=listen/' /data/local/tmp/.gsys/settings.conf"
adb shell su -c 'sh /data/adb/modules/zygisk_gadget_stealth/gadget_ctl.sh reload'
```

## 生效条件（容易搞混）

| 改了什么 | 需要做什么 |
|---|---|
| 任何 `settings.conf` 项 | `reload` + **force-stop 并重启目标 App** |
| `hook.js` | 重启目标 App（`on_change=reload`） |
| 增删目标 App | `reload` + 启动那个 App |
| 安装 / 卸载模块 | **重启手机**（Zygisk 模块在 zygote fork 时加载） |
| 替换 gadget so | `reload`（会重新 `chcon` 修正 SELinux） |

不需要重启手机是刻意设计的：gadget 只在 App 启动时注入，配置是每次 App 启动时重新读的。

## 两个模式的 gadget config

`reload` 按 `lib_name` 的 basename 生成（so 名 `libgcore.so` → `libgcore.config`），同时写一份 `.config.so` 兼容副本。

**script**（默认）：

```json
{"interaction":{"type":"script","path":"/data/local/tmp/.gsys/hook.js","on_change":"reload"}}
```

**listen**：

```json
{"interaction":{"type":"listen","address":"127.0.0.1","port":27052,
  "on_port_conflict":"pick-next","on_load":"resume"}}
```

`on_load=resume` 很关键：gadget 默认是 `wait`，会阻塞 App 启动直到客户端 attach，表现为 App 白屏不动。

## 数据目录换位置

```bash
su -c 'echo /data/local/tmp/.cache2 > /data/local/tmp/.gsys_redirect'
# 或
su -c 'sh /data/adb/modules/zygisk_gadget_stealth/gadget_ctl.sh datadir /data/local/tmp/.cache2'
```

native 模块每次 App 启动都会读重定向文件。改完记得把 `libgcore*.so` / `settings.conf` / `hook.js` 复制过去并执行 `reload`（`reload` 会按新目录重新生成 config 并修正 SELinux context）。

## SELinux 注意

`/data/local/tmp` 下新建文件默认是 `u:object_r:shell_data_file:s0`，`untrusted_app` 域**没有 execute 权限**，直接 `dlopen` 会失败并在 logcat 留下：

```
avc: denied { execute } for path="/data/local/tmp/.gsys/libgcore.so"
  scontext=u:r:untrusted_app:s0 tcontext=u:object_r:shell_data_file:s0
```

安装脚本与每次 `reload` 都会执行 `chcon -R u:object_r:system_file:s0`。

不过「手动替换过 so / js 后必须 reload」这个说法要收窄——**不是所有替换都会丢标签**：

| 替换方式 | 需要补 `chcon` 吗 |
|---|---|
| `cp` 复制进 `.gsys` | 不用，新建文件自动继承目录标签 |
| 编辑器原地改 / 临时文件改名覆盖 | 不用，标签不变或继承目录 |
| `mv` 从 `/data/local/tmp` 等处搬进来 | **要**，rename 保留源文件的 `shell_data_file` |
| 删除并重建 `.gsys` 目录 | **要**，目录退回 `shell_data_file`，内容全部沦陷 |

判断：`ls -Z /data/local/tmp/.gsys/<文件>`；补救：`gadget_ctl.sh reload`。完整实测判据见 `手机端使用说明.md` 第 3.1 节。

## 常见错误

| 现象 | 原因与处理 |
|---|---|
| `status1` 里 `loaded=0` | 装完没重启，或 Zygisk 实现未启用。查 `su -c 'cat /data/adb/zygisksu/modules_info'` |
| 状态文件 `ok=0;detail=dlopen-failed` | 多半是 SELinux context 不对，执行 `reload` 后看 `ls -lZ` 是否为 `system_file` |
| App 白屏卡住 | gadget 用了默认 `on_load=wait`；确认 `libgcore.config` 里是 `script` 或 `on_load=resume` |
| listen 模式连不上 | 检查端口是否被占用、`adb forward` 是否建立、是否被 `pick-next` 换到了别的端口 |
| 32 位 App 不注入 | `lib_name32` 指向的 so 是否存在；`check1` 里 `lib32` 是否为 1 |
| WebUI 数值全是 `-` | 管理器不支持 `ksu.exec`；用「执行」按钮或 PC 端 `tools/status.py` |
