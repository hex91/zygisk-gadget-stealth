# 手机端使用说明（持久化 hook）

> 面向「装好模块之后，脚本放哪、怎么写、怎么让它每次都自动跑」。
> PC 端连上去交互调试的流程见 [PC端使用说明.md](PC端使用说明.md)。
> 本文所有命令与结论均在 Pixel 6 / Android 15 / frida-gadget 17.5.2 上实测。

---

## 1. 先建立心智模型

```
开机 → Zygisk 加载模块 so → 目标 App 启动（zygote fork 出新进程）
                                    ↓
                       模块 so 在 App 进程里 dlopen gadget（延迟 delay_ms）
                                    ↓
              gadget 读 <lib_name>.config → script 模式 → 加载 hook.js
                                    ↓
                        hook.js 执行（每次 App 启动都会重新执行一次）
```

三条关键推论：

1. **持久化是天然成立的**：不需要守护进程、不需要 PC 在线。只要 App 启动，脚本就跑。
2. **脚本生命周期 = 进程生命周期**：App 被 force-stop / 被杀 / 你手动退出，脚本随之消失；重新启动 App 会重新跑一遍 `hook.js`。
3. **`hook.js` 只在注入那一刻读一次**：改完必须 force-stop + 重启 App，光 `reload` 不够（`reload` 只重写 `gadget.config`）。

## 2. 文件都在哪

| 作用 | 路径 | 谁读 |
|---|---|---|
| 主配置 | `/data/local/tmp/.gsys/settings.conf` | 模块 so（每次 App 启动） |
| 你的 hook 脚本 | `/data/local/tmp/.gsys/hook.js` | gadget（每次注入） |
| gadget 行为配置 | `/data/local/tmp/.gsys/libgcore.config` | gadget（每次注入） |
| 64 位 gadget | `/data/local/tmp/.gsys/libgcore.so` | 模块 so |
| 32 位 gadget | `/data/local/tmp/.gsys/libgcore32.so` | 模块 so |
| 控制脚本 | `/data/adb/modules/zygisk_gadget_stealth/gadget_ctl.sh` | 你 / WebUI |
| 脚本日志（模板自带） | `/data/user/0/<包名>/gs-hook.log` | 你 |
| 注入状态记录 | `/data/user/0/<包名>/.gs_state.<pid>` | WebUI / `status` |

两个目录的权限差异很重要：

- `/data/local/tmp/.gsys` 是 `system_file` 上下文，App 进程**只能读不能写** —— 脚本放这儿，App 自己改不掉，也算一种防篡改。
- `/data/user/0/<包名>/` 是 App 私有目录，App 能写 —— 所以**日志写在 App 自己目录里**，这也是模板里那段 `LOGPATH` 的由来。

## 3. 第一次跑通（5 步，约 2 分钟）

```bash
# 1) 准备模板（PC 上执行）
adb push docs/hooks/00-hello.js /data/local/tmp/gs_hello.js

# 2) 放到 gadget 会读的位置（覆盖默认 hook.js）
adb shell su -c 'cp /data/local/tmp/gs_hello.js /data/local/tmp/.gsys/hook.js'
adb shell su -c 'chmod 644 /data/local/tmp/.gsys/hook.js'
adb shell su -c 'chcon u:object_r:system_file:s0 /data/local/tmp/.gsys/hook.js'

# 3) 确认是 script 模式（默认就是）
adb shell su -c 'sh /data/adb/modules/zygisk_gadget_stealth/gadget_ctl.sh status1'

# 4) 重启目标 App（必须，脚本只在注入时读一次）
adb shell am force-stop com.example.app
adb shell monkey -p com.example.app -c android.intent.category.LAUNCHER 1

# 5) 看证据
adb shell su -c 'cat /data/user/0/com.example.app/gs-hook.log'
```

日志里出现 `=== gs-hello === pid=… arch=arm64 pkg=… frida=17.5.2` 就说明链路全通。

> 不用 WebUI 也能干这些事；WebUI 只是把 `gadget_ctl.sh` 的这几个子命令做成了按钮。

## 4. 脚本怎么写（三条硬规则）

### 规则一：frida 17 没有内置 `Java`

实测 17.5.2 的 gadget：`typeof Java === 'undefined'`。所以**纯 Java 的 hook 脚本不能直接扔进 `hook.js`**，必须用 `frida-compile` 把 `frida-java-bridge` 一起打包：

```js
import Java from 'frida-java-bridge';   // 这行只有打包后才有意义

Java.perform(function () {
  var Cipher = Java.use('javax.crypto.Cipher');
  // ...
});
```

直接把这个文件当 `hook.js` 会报：

```
SyntaxError: expecting '('        # QJS 不认识 import
Java is not defined               # 去掉 import 之后的报错
```

打包见第 7 节。**纯 Native hook（Interceptor）不需要打包**，单文件直接放。

### 规则二：`Module.findExportByName` 已被移除

frida 17 删了全局形式，实测：

| 写法 | 17.5.2 结果 |
|---|---|
| `Module.findExportByName(null, 'dlopen')` | `undefined`（调用即 `TypeError: not a function`） |
| `Module.getExportByName('libssl.so', 'SSL_read')` | 同样是 `undefined` |
| `Module.findGlobalExportByName('dlopen')` | ✅ 返回地址 |
| `Process.getModuleByName('libssl.so').findExportByName('SSL_read')` | ✅ 返回地址 |

模板里已经封装成兼容函数，抄这段就行：

```js
function findGlobal(name) {
  if (typeof Module.findGlobalExportByName === 'function')
    return Module.findGlobalExportByName(name);
  return Module.findExportByName(null, name);      // frida 16 及更早
}
function findIn(moduleName, name) {
  var m = Process.findModuleByName(moduleName);
  return m ? m.findExportByName(name) : null;
}
```

### 规则三：script 模式没有 console 接收者，日志要落盘

`script` 模式下没有客户端连着，`console.log` 直接进黑洞。模板统一用这段（实测可写、可读回）：

```js
var PKG = (function () {                     // 读 /proc/self/cmdline 拿包名
  var raw = File.readAllBytes('/proc/self/cmdline');
  var u8 = new Uint8Array(raw), s = '';
  for (var i = 0; i < u8.length && u8[i] !== 0; i++) s += String.fromCharCode(u8[i]);
  return s.split(':')[0];                    // 去掉 :remote 之类后缀
})();
var LOGPATH = '/data/user/0/' + PKG + '/gs-hook.log';
```

注意两点：

- 读 `cmdline` 必须用 `File.readAllBytes`，`File.readAllText` 会因为 NUL 字节报 `can't decode byte 0x00`。
- 如果你 hook 了 `open/openat`，**写日志会再次触发 hook** —— 模板用 `IN_LOG` 标志掐断递归，自己写的时候别忘了。

另外 17.5.2 的脚本运行时是 **QJS（QuickJS）**，不是 V8：语法基本够用，但 `require`、部分新语法、以及依赖 V8 行为的库要小心。

## 5. 参数意义（`settings.conf`）

改完任何一项都要：

```bash
adb shell su -c 'sh /data/adb/modules/zygisk_gadget_stealth/gadget_ctl.sh reload'
adb shell am force-stop <包名> && adb shell monkey -p <包名> -c android.intent.category.LAUNCHER 1
```

| 键 | 默认 | 含义 | 生效条件 |
|---|---|---|---|
| `enabled` | `1` | 全局总开关，`0` 完全不注入（模块仍加载） | reload + 重启 App |
| `mode` | `script` | `script` 无端口自动执行 hook.js；`listen` 监听端口等客户端 | reload + 重启 App |
| `port` | `27052` | 仅 `listen` 用；避开 27042 / 39527；冲突时 `pick-next` 自动换 | reload + 重启 App |
| `delay_ms` | `1200` | 注入延迟，等 App 启动期完整性检查跑完再注入 | reload + 重启 App |
| `lib_name` | `libgcore.so` | 64 位 gadget 的伪装文件名，**不要带 frida/gadget 字样** | reload + 重启 App |
| `lib_name32` | `libgcore32.so` | 32 位 gadget 文件名 | reload + 重启 App |
| `hide_maps` | `1` | 把 gadget 的 maps 段重映射成匿名内存，扫不到文件路径 | reload + 重启 App |
| `hide_module_map` | `0` | 连 Zygisk 模块自身 so 也匿名化（实验性） | reload + 重启 App |
| `hide_threads` | `1` | 把 `gum-js-loop` / `frida-gadget` / `gmain` / `gdbus` 改名 | reload + 重启 App |
| `thread_alias` | `auto` | `auto` 从真实 ART/App 线程名池轮换；填字符串则 `<前7字符>-<tid>` | reload + 重启 App |
| `no_log` | `1` | 不向 logcat 输出（排查时临时改 `0`） | reload + 重启 App |
| `write_state` | `1` | 写 `.gs_state.<pid>` 供 WebUI 显示「最近注入」 | reload + 重启 App |
| `target` | `包名,1,1200` | 目标行：`包名,是否启用,该 App 的延迟`，可写多行 | reload + 重启 App |
| `hook.js` 内容 | — | 脚本本体 | **只改文件不够，必须重启 App** |

命令行改参数比手工编辑更安全（会同时重写 `libgcore.config`）：

```bash
CTL=/data/adb/modules/zygisk_gadget_stealth/gadget_ctl.sh
adb shell su -c "sh $CTL mode script"
adb shell su -c "sh $CTL port 27052"
adb shell su -c "sh $CTL delay 1500"
adb shell su -c "sh $CTL add com.example.app"
adb shell su -c "sh $CTL disable com.example.app"
adb shell su -c "sh $CTL stealth hide_maps 0"
adb shell su -c "sh $CTL targets"
```

## 6. 持久化：到底持久在哪

| 场景 | 结果 |
|---|---|
| 手机重启 | 模块 so 由 Zygisk 重新加载；App 启动时照常注入（前提 `enabled=1`） |
| App 被 force-stop 后再启动 | 重新注入、重新执行 `hook.js` |
| App 在后台被杀（内存回收） | 下次启动重新注入 |
| 升级模块（`ksud module install`） | 写入 `modules_update`，**必须重启手机**才换到新 so |
| 只改 `settings.conf` | `reload` + 重启 App，不用重启手机 |
| 只改 `hook.js` | 重启 App（`reload` 不够） |
| 临时停用但保留模块 | `gadget_ctl.sh off`（等价 `enabled=0` + reload） |
| 彻底卸载 | `ksud module uninstall zygisk_gadget_stealth` 后重启 |

**验证「真的持久」的标准动作**：

```bash
adb reboot
# 等开机完成，启动目标 App
adb shell su -c 'cat /data/user/0/<包名>/gs-hook.log' | tail -3   # 时间戳应是刚开机
adb shell su -c 'sh /data/adb/modules/zygisk_gadget_stealth/gadget_ctl.sh status1'
# active 计数 +1，last=<包名>:<新pid>
```

想确认「这个 App 确实被注入了」，看三处任一即可：

1. `status1` 的 `active` / `last`；
2. `/data/user/0/<包名>/gs-hook.log` 里最新一行的时间戳；
3. `adb shell su -c 'ls /data/user/0/<包名>/.gs_state.*'`。

## 7. 工程化：脚本多了怎么管

### 方案 A：单文件（最简单）

纯 Native 的脚本直接堆在一个 `hook.js` 里，用 IIFE 分块，注意顺序：

```js
(function () { /* ssl 抓包 */ })();
(function () { /* jni 追踪 */ })();
```

### 方案 B：`frida-compile` 打包（Java 脚本必须走这条）

`docs/hooks/` 里已经配好：

```bash
cd docs/hooks
npm install                      # 首次
npm run build                    # 产出 dist/02-ssl-bypass.js、dist/03-crypto-hook.js
```

产物约 520 KB（内联了 java bridge），推到手机当 hook.js：

```bash
adb push docs/hooks/dist/02-ssl-bypass.js /data/local/tmp/gs_ssl.js
adb shell su -c 'cp /data/local/tmp/gs_ssl.js /data/local/tmp/.gsys/hook.js'
adb shell su -c 'chcon u:object_r:system_file:s0 /data/local/tmp/.gsys/hook.js'
adb shell am force-stop <包名>
```

自己写新脚本时，在 `docs/hooks/` 下建 `05-myhook.js`，`package.json` 里加一条：

```json
"build:myhook": "frida-compile 05-myhook.js -o dist/05-myhook.js -c"
```

### 方案 C：多个脚本合成一个入口

`frida-compile` 支持 `import './part2.js'` 这种本地模块拆分（打包后自动合并）：

```js
// entry.js
import './ssl.js';
import './crypto.js';
import Java from 'frida-java-bridge';
Java.perform(function () { /* ... */ });
```

注意：**运行时没有 `require`**，gadget 不会去磁盘找模块，所有依赖必须在打包时静态内联。

## 8. 模板清单（都在 `docs/hooks/`）

| 模板 | 需要打包 | 干什么 | 关键参数 |
|---|---|---|---|
| `00-hello.js` | 否 | 验证链路：打印 pid/arch/包名/frida 版本/已加载 so，写日志 | 无 |
| `01-native-trace.js` | 否 | so 加载、文件打开、SSL 明文、strcmp | `CFG.ssl` / `CFG.files` / `CFG.fileKeyword` / `CFG.strcmp` |
| `02-ssl-bypass.js` | ✅ | TrustManager / OkHttp Pinner / HostnameVerifier / Conscrypt | 无（默认全开） |
| `03-crypto-hook.js` | ✅ | Cipher / Digest / HMAC / SecretKeySpec / IV / Base64 | `CFG.algoFilter` / `CFG.maxBytes` / `CFG.printKey` |
| `04-jni-register.js` | 否 | 枚举 `RegisterNatives` 注册的 native 方法并追踪调用 | `CFG.dumpAll` / `CFG.watch` / `CFG.dumpArgs` |

### 8.1 `00-hello.js` —— 先确认链路

什么都不改，日志里应看到 `pkg = <包名>`、`frida = 17.5.2`、`modules = 338` 左右。

### 8.2 `01-native-trace.js` —— 不知道从哪下手时先跑它

```js
var CFG = {
  dlopen: true,
  files: false,          // 打开文件（量大，先关）
  fileKeyword: '',       // 只想看 .so 就填 '.so'
  ssl: true,             // 抓 SSL 明文
  strcmp: false,
  strcmpKeyword: 'licen',
  maxBytes: 200
};
```

实测输出（`SSL_read` / `SSL_write` 都已挂上）：

```
[ssl] hooked SSL_read @ 0x7810b88844
[ssl] hooked SSL_write @ 0x7810b88c70
[ssl C->S] SSL_write 183B "POST /api/login HTTP/1.1\r\nHost: ..."
[ssl S->C] SSL_read 512B "HTTP/1.1 200 OK\r\n..."
```

> 有些 App 用 Cronet 或自带静态 BoringSSL，`libssl.so` 里找不到符号，脚本会打印「未找到」，此时改用 `02-ssl-bypass.js` 在 Java 层动手。

### 8.3 `02-ssl-bypass.js` —— 抓包过 pin

四道常见防线一次打完（每一道独立 try/catch，缺哪个只打 `[skip]` 不影响其他）：

| 防线 | 做法 | 实测 |
|---|---|---|
| 全局 `SSLContext.init` | 换上 trust-all 的 `X509TrustManager` | `[ok]` |
| Conscrypt `TrustManagerImpl.verifyChain` | 直接返回原链 | `[ok]` |
| OkHttp `CertificatePinner.check` | 空实现 | App 没用 okhttp 时 `[skip]`（正常） |
| `HostnameVerifier` 各实现 | `verify()` 返回 `true` | 命中 3 个实现 |

配合 `01` 的 SSL 明文，或者 PC 端 mitmproxy / Charles 一起用。

### 8.4 `03-crypto-hook.js` —— 抓算法、key、明文

默认只关心 `AES|DES|RSA|HMAC|SHA|MD5|SM4|SM3`，避免刷屏。典型输出：

```
[key   ] AES len=16B hex=30313233343536373839616263646566
[iv    ] len=16B hex=000102...0f
[cipher] AES/CBC/PKCS5Padding in=48B hex=7b22757365... | "{"user":"admin","ts":17..."
[cipher] AES/CBC/PKCS5Padding out=64B hex=9f3c... 
[digest] SHA-256 in=32B hex=... out=ab12...
[b64   ] in=64B -> 9f3c8a...
```

拿到 key / iv / 明文后，签名逻辑基本可以在 PC 上离线复现。

### 8.5 `04-jni-register.js` —— 动态注册的 native 方法

加固和风控常把核心逻辑放在 `RegisterNatives` 注册的函数里，Java 层看不到实现。这个模板在注册那一刻把映射全打出来（实测从 `libart.so` 的符号表里定位到了 `art::JNI::RegisterNatives`）：

```
[jni] RegisterNatives @ 0x784e45d1ec (_ZN3art3JNIILb0EE15RegisterNativesEP7_JNIEnvP7_jclassPK15JNINativeMethodi)
[jni-reg] nativeSign(Ljava/lang/String;)[B -> 0x7a1c40d200
[jni-reg] nativeCheck()Z -> 0x7a1c40d380
[jni-call] nativeSign(Ljava/lang/String;)[B tid=12345 a0=0x7ffd... a1=0x7a1c...
```

两步走：先 `dumpAll: true` 拿清单，再把关心的名字填进 `CFG.watch` 重跑，就能看到调用参数。

## 9. 常见故障对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| `SyntaxError: expecting '('` | 把带 `import` 的 Java 脚本直接当 hook.js | 用 `frida-compile` 打包 |
| `Java is not defined` | 同上，去掉了 import 但没打包 | 同上 |
| `TypeError: not a function`（`Module.findExportByName`） | frida 17 删了这个 API | 用 `findGlobal` / 模块实例 `findExportByName` |
| 日志文件没生成 | 读 `cmdline` 失败或目录不可写 | 用 `File.readAllBytes`；确认包名正确 |
| 改了 hook.js 没反应 | 没重启 App | force-stop + 重启 |
| App 启动白屏 / 卡住 | 脚本死循环、或注入时机太早 | 加大 `delay_ms`；检查 `while` / 递归 hook |
| `no_log=0` 也没 logcat | 脚本没被加载（模式不是 script、目标没匹配） | `status1` 看 `active`；`check1` 看 `hook=1` |
| `ls -Z` 显示 `shell_data_file` | SELinux 上下文错 | `chcon u:object_r:system_file:s0 <文件>` 或 `gadget_ctl.sh reload` |
| 32 位 App 不注入 | 缺 `libgcore32.so` | `check1` 看 `lib32` |

排错三件套：

```bash
CTL=/data/adb/modules/zygisk_gadget_stealth/gadget_ctl.sh
adb shell su -c "sh $CTL status"          # 完整面板
adb shell su -c "sh $CTL check1"          # 单行自检
adb shell su -c "sh $CTL log"             # logcat（no_log=0 时才有内容）
adb shell su -c 'ls -lZ /data/local/tmp/.gsys'
```

## 10. 边界

- 只对 `target` 白名单里的 App 生效，别的进程完全无感。
- 一个进程只能有一份 Gum：**不要再用 frida-server attach 已加载 gadget 的进程**，两份 Gum 会互相踩 inline hook。
- 状态文件、`gs-hook.log` 都是调试辅助，正式使用可以关掉（`write_state=0`、删掉日志段落）。
- 仅限自有设备或已授权目标的安全研究用途。
